候选集生成模型

YouTube 要把海量视频缩到几百个候选交给排序层。候选集生成模型把这件事当成一个多分类问题：输入是用户的历史观看向量与搜索词向量，输出是在所有视频上的概率分布，取概率最高的一批作为候选。训练用负采样，线上用最近邻搜索。

这一步在系统里做什么

如 8.3.2 节所述，YouTube 的推荐系统是两级漏斗：先用候选集生成（召回）从百万级视频库里筛出几百个，再由排序模型精细打分。候选集生成这一步的任务不是精确排序，而是“不漏掉大体相关的视频”，同时把规模降下来。

在 YouTube 的设计里，这被建模成一个多分类问题：给定用户当前的上下文，预测他下一个会观看哪个视频。类别数量等于视频库大小，模型的输出就是在这几十万/百万类别上的概率分布。

模型架构：三层结构

如图 8-15（本仓讲义引用的原书图）所示，模型从下到上可分为三层：

  1. 输入层：用户历史观看视频的 Embedding 向量与搜索词 Embedding 向量（以及其他用户特征）。前者捕捉长期观看偏好，后者反映即时需求。
  2. 中间层：一个 Embedding 层（对视频与搜索词预训练）加上三层 ReLU 神经网络，对拼接后的特征做非线性变换。
  3. 输出层：softmax 层把输出变成在所有候选视频上的概率分布，即“用户观看下一个视频的概率”。

Embedding 从哪里来

要让 softmax 能预测“下一个视频”，首先得把用户看过的视频、搜过的词变成向量。讲义指出，YouTube 生成视频 Embedding 与搜索词 Embedding 的方法与 Airbnb 相似：

  1. 数据准备：收集用户的历史观看序列与搜索序列。
  2. 模型训练：用 Word2vec 方法对视频与搜索词做 Embedding；同时在网络中增加 Embedding 层，与上层的 DNN 一起端到端训练。

除了行为序列，模型还使用两类特征：用户侧的地理位置、年龄、性别等信息（捕捉背景），以及视频侧的标题、描述、标签、上传时间、观看/点赞数等（捕捉语义与受欢迎程度）。

训练与线上服务

训练时，若对百万级视频做完整 softmax，开销太大。YouTube 使用负采样：只对真实观看过的视频（正样本）与少量采样出来的视频（负样本）计算，从而减少每次预测的分类数量，加快收敛。这和第 4.2 节 Word2vec 的负采样是同一思路。

线上服务时，不必真的跑一遍完整 softmax。既然网络后几层近似一个可分解的内积形式，就可以把用户向量与视频向量预先算好、存入内存数据库，再用最近邻搜索（内积运算 + 排序；讲义也提到局部敏感哈希等快速搜索方法）得到候选集。这与第 4.6 节“用 LSH 加速 Embedding 近邻搜索”的思路一致。

小结

候选集生成模型把“召回”写成了一个多分类问题：输入观测/搜索向量，中间三层 ReLU，顶部 softmax 输出全视频库概率；训练靠负采样，服务靠最近邻搜索。它的两大看点——把大规模候选生成转成分类问题、以及用 Embedding + 近邻搜索取代逐条打分——也是 Embedding 技术（第 4 章）在工业系统里最直接的落地。
